# Production readiness ladder

TeamVault runs on one machine. The rule for this project is: everything that makes an
application safe to run as several instances and costs nothing but discipline is built from
the start; everything that needs infrastructure of its own (a cache server, a message broker,
a cluster) is built in the sprint that pays for it, and named here until then.

Three statuses:

- **built**: in the code, with a test or an ADR where the decision was real.
- **sprint N**: on the plan, with the sprint it lands in.
- **named**: known, understood, not built in this cycle. The alternative is written down so
  the omission is a decision and not a gap.

## What two instances would need today

Nothing in the request path keeps state in the process: tokens are self-contained (ADR-004),
authorization is a database lookup per request (ADR-003), ids are generated by the
application, and the schema is owned by migrations. Two backends behind one proxy would
share the database and work, with one exception: the blob store writes to the local file
system. That is the single two-instance blocker, and the S3-compatible store in Sprint 3
removes it. From then on the ladder below adds what makes several instances observable and
cheap to run, not what makes them possible.

## Data and storage

| Item | Status | Note |
|---|---|---|
| Schema owned by Flyway, Hibernate validates only | built | ADR-001 |
| Tenant-scoped unique constraints and composite indexes | built | `docs/erd.md`, one justification per index |

| Blob store behind one interface | built | `FileStorage`, local file system |

| Storage quotas per tier, enforced on upload | sprint 4 | The tier column exists, the enforcement does not |

## API contract

| Item | Status | Note |
|---|---|---|
| One error shape for every failure path, including the 401 from the filter chain | built | The entry point delegates to the MVC resolver; the advice is the one writer |
| Problem Details (RFC 9457) instead of the custom error record | built | ADR-005; `type` is an anchor into `docs/errors.md`, the advice extends `ResponseEntityExceptionHandler` |
| Request id in the error body and in the log line | built | `RequestIdFilter` ahead of the security chain, `X-Request-Id` on every response, `requestId` in every problem body |
| OpenAPI document generated from the controllers | built | springdoc 3.x, bearer scheme global, Problem Details on every error response, exported to `docs/openapi.yaml` by the test suite |
| Frontend client generated from the OpenAPI document | sprint 3 | Hand-mirrored schemas drift at runtime, generated types drift at build time |
| API versioning | named | Path or media type; one client today, no version needed |
